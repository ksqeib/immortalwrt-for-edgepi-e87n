# 风扇实测（2026-10-09）

## 结论

**这台风扇对 SoC 温度的作用不到 1 °C**，满载与空载都是。瓶颈在 die 到散热片
之间的热阻（导热垫偏厚），风扇吹的是散热片，而散热片不是热瓶颈，所以转速从停到
满速都换不来温度。

风扇**只吹 CPU 侧散热片**，够不到两个 NVMe 槽，所以连「顺带吹吹别的部件」这层
意义也没有。风扇曲线的意义只剩一个：**别在没用的地方白转（噪音）**。它不是一个能
用来压 SoC 温度的旋钮。

## 测量方法

`tools/fan-sweep.sh`。它先 `echo disabled > thermal_zone0/mode` 停掉内核治理
——**不停的话 `pwm1` 写不动**，governor 每轮治理都会把 `pwm1` 改回当前档位值——
然后逐档写 `pwm1`、每档等一段时间、读 `thermal_zone0/temp`，退出时恢复原状态。

空载：`sh /tmp/fan-sweep.sh 20`

满载：`sh /tmp/fan-sweep.sh load 40`（拉起 4 个 `yes` 占满四核，满速预热 30 秒到
稳态后开扫）

## 数据

### 空载

| PWM | 温度 | 相对上一档 |
| --- | --- | --- |
| 0 | 54.9 °C | — |
| 64 | 55.6 °C | +0.7 |
| 128 | 54.8 °C | −0.8 |
| 192 | 55.1 °C | +0.3 |
| 255 | 54.1 °C | −1.0 |

### 满载（四核跑满）

| PWM | 温度 | 相对上一档 |
| --- | --- | --- |
| 0 | 72.8 °C | — |
| 64 | 74.6 °C | +1.8 |
| 128 | 74.9 °C | +0.3 |
| 192 | 73.4 °C | −1.5 |
| 255 | 72.0 °C | −1.4 |

两个工况下，0 档到满速的净差都是 **0.8 °C**，而相邻档之间的抖动有 ±1.5 °C。
也就是说这条曲线里的起伏全是噪声，风扇转速对 SoC 温度的影响落在测量误差里。

满载 72.8 °C 也说明一件事：**即使风扇完全不转，满负载也只有 73 °C**，离 117 °C
的 active-hot 与 125 °C 的 critical 都很远。所以散热余量是够的。

## 曲线怎么改的

原来的 trip 是 `52/68/80 °C`，待机 55 °C 就进了第一档（PWM 110），而这一档实测
毫无作用——等于白转。

改成 `62/72/82 °C`：

| 温度 | 档位 | PWM | 说明 |
| --- | --- | --- | --- |
| ≤ 62 °C | 0 | 0 | 停转。待机约 55 °C 停在这里 |
| 62 °C | 1 | 110 | 刚过起转阈值 |
| 72 °C | 2 | 175 | 四核满载约 73 °C，停在这里 |
| 82 °C | 3 | 255 | 满速，仍比 critical 低 35 °C |

`cooling-levels` 本身没动（`<0 110 175 255>`），改的是 trip 阈值。

## 没做的事

- **没关内核热管理**。原厂 `fancontrol` 与第三方 `luci-app-Airpifanctrl` 都会
  `echo disabled > thermal_zone0/mode` 然后自己写 `pwm1`，那样内核兜底就没了。
  我们的方案留在 thermal 框架里，掉电重启、脚本挂掉都还有保护。
- **没上 25 档曲线**。那是给上面那个守护进程用的，脱离它没有意义。
- **没换散热垫**。这是唯一能真正改善 SoC 温度的做法，但属于硬件改造，不在本移植
  范围内，记在这里备查。风扇只吹 CPU 侧散热片，两个 NVMe 槽在另一侧，不在它的
  风路上。
